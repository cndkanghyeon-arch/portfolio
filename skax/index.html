일하는 순서

모호한 요구를 명세로 바꾸는 순서를 고정해 두었습니다

순서가 고정돼 있어야 요구사항이 바뀌어도 일정과 범위를 되짚을 기준이 남습니다.

Step 01

현업 옆에서 실측

요구사항을 회의실에서 받지 않고 담당자 옆에서 업무를 관찰하고 건수와 소요 시간을 직접 잽니다. 숫자가 있어야 범위를 깎을 때도 무엇을 깎는지 서로 압니다.

Step 02

정책과 화면, 데이터를 한 기준으로

정책정의서와 화면기획서, IA, ERD, API 명세를 같은 기준으로 묶어 직접 씁니다. 개발팀이 해석할 여지를 남기지 않아야 통합 테스트에서 터지지 않습니다.

Step 03

진척을 로그로 추적

보고를 받아서 진척을 아는 구조를 만들지 않습니다. Jira와 Flow 로그를 모아 지연 Task와 누락을 자동으로 띄우고, 산정식과 출처를 공개해 같은 숫자로 논의합니다.
