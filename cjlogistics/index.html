공개된 자료에서 포워딩 IT 조직이 지금 다루는 문제를 찾고, 제가 겹치는 지점과 겹치지 않는 지점을 나눠 봤습니다.

국가가 늘어날수록 어려워지는 것은 기능이 아니라 기준입니다

확인한 사실

  • TES는 Technology, Engineering, System and Solution을 뜻하고 연구소는 미래기술개발, SCM컨설팅, 운영최적화, 데이터분석 네 팀으로 구성
  • 글로벌사업은 포워딩사업과 해외사업으로 나뉘고, 전 세계 39개국 115개 법인을 기반으로 운영
  • 글로벌 통합 포워딩 시스템 큐브릿지를 운영하며, 국가별 특성을 반영한 큐브릿지 2.0을 미국과 중국 등 해외 9개국으로 확대 적용
  • 단순 반복 서류 업무에 RPA를 적용하고 화물선 도착일시 예측에 AI를 붙였으며, LoIS 포워더스에서는 출발지와 도착지, 크기와 무게만 넣으면 실시간 견적을 조회

그래서 생기는 문제와 제 접점

  • 같은 시스템을 9개국으로 넓히면 나라마다 규정과 서류가 달라 분기가 쌓입니다. 저는 170개국 규정을 코드가 아니라 설정값 기반 분류 체계로 바꿔 규정이 바뀌어도 시스템을 고치지 않게 만들었습니다
  • 선사와 항공사, 통관, 고객사가 각각 다른 규격으로 데이터를 보냅니다. 저는 외부 시스템 네 곳의 연동 프로토콜을 분석하고 파라미터명을 자사 기준으로 매핑했으며, 문서가 실제 응답과 달라 기관 담당자와 직접 협의해 명세를 다시 썼습니다
  • 연계가 늘수록 숫자가 서로 어긋납니다. 저는 두 시스템 사이 API 데이터를 자동으로 대조하고 어긋난 값을 자동 수정하도록 만들어 월 마감 대사 작업을 없앴습니다
  • 반복 서류와 리포트는 사람이 계속 만들면 늘어납니다. 저는 업무 시간을 직접 재서 과제를 고르고 14종을 만들어 전부 운영에 안착시켰습니다

일하는 순서

표준을 먼저 세우고 연동을 붙입니다

연동을 먼저 붙이고 표준을 나중에 맞추면 국가가 늘어날 때마다 같은 일을 반복하게 됩니다. 세 단계를 그대로 재사용합니다.

Step 01

기준 정리

바뀌는 것과 바뀌지 않는 것을 먼저 나눕니다. 바뀌는 쪽은 설정값으로 빼고 유형별 기본값을 제공합니다. 예외는 별도로 분리해 본류를 오염시키지 않습니다.

Step 02

연동 설계

상대 시스템의 문서를 그대로 믿지 않습니다. 실제 호출로 응답을 확인하고 파라미터를 하나씩 검증한 뒤 명세를 다시 씁니다. 실패 시 재처리 경로까지 문서로 남깁니다.

Step 03

상시 점검

월 마감에만 보던 정합성 점검을 상시로 돌려 이상이 먼저 보이게 합니다. 사람이 찾아내기 전에 시스템이 먼저 알리는 쪽이 복구 비용이 쌉니다.
